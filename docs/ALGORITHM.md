# 调和分析算法说明

本文档说明后端中**分潮判别、最小二乘拟合、潮流椭圆换算**三块手写数学的约定、
判据与取舍。实现见 `app/harmonics.py` 与 `app/service.py`，没有使用任何现成的
潮汐分析库。

## 1. 时间与分潮频率

* 时间原点固定为**测站布放时刻** `deployed_at`（UTC），所有拟合都在“距布放的
  小时数” `t` 上进行，而不是日历时刻。这样同一测站跨批次、跨重启的拟合完全一致。
* 采样必须落在以布放时刻为零、以 `sample_interval_seconds` 为步长的等间隔网格上
  （容差：相对 1e-9，绝对 1 ms）。网格上跨步 > 1 即表示中间有缺测段；缺测点也可
  显式以 `u/v = null` 上报。

候选分潮频率（相位推进速率，度/平均太阳时；换算为拟合用的弧度/小时与判别用的
周/小时）：

| 分潮 | 度/小时 | 周/小时 | 弧度/小时 |
|------|---------|---------|-----------|
| M₂ | 28.9841042 | 0.0805114 | 0.50586805 |
| S₂ | 30.0000000 | 0.0833333 | 0.52359878 |
| N₂ | 28.4397295 | 0.0789992 | 0.49636666 |
| K₂ | 30.0821373 | 0.0835615 | 0.52503108 |
| K₁ | 15.0410686 | 0.0417807 | 0.26251554 |
| O₁ | 13.9430356 | 0.0387307 | 0.24334888 |

平均流（mean）频率为 0，恒纳入。

## 2. 单分潮模型与最小二乘

每个纳入的分潮 k 用余弦/正弦两个基函数表示，t 为距布放的小时数：

```
u(t) = mean_u + Σ [ a_u,k cos(ω_k t) + b_u,k sin(ω_k t) ]
v(t) = mean_v + Σ [ a_v,k cos(ω_k t) + b_v,k sin(ω_k t) ]
```

设计矩阵 `A` 列顺序固定：第 0 列常数 1；第 k 个分潮（从 1 起）占第 `2k-1`
列 cos、第 `2k` 列 sin。`u`、`v` 分别求解同一正规方程

```
Aᵀ A · x = Aᵀ y
```

正规矩阵与右端项由代码显式累加（`np.einsum` 做外积/内积求和），**不调用**
`lstsq / pinv / QR` 等最小二乘例程；只把最后的对称线性方程组交给
`numpy.linalg.solve`。极短记录导致矩阵奇异时，退化为 SVD 伪逆的最小范数解
（不可辨识的系数取零），服务不因此报错。

含缺测（`u` 或 `v` 非有限/为 null）的行在组装前剔除；时间本身不允许缺测。

分量振幅与相位：

```
U = hypot(a_u, b_u),   φ_u = atan2(b_u, a_u) ∈ [0, 2π)
V = hypot(a_v, b_v),   φ_v = atan2(b_v, a_v) ∈ [0, 2π)
```

## 3. 分潮纳取判据（Rayleigh 准则 + 非对称占位）

### 3.1 判据

频率以周/小时计，经典 Rayleigh 判据取 R = 1。候选分潮 c 必须同时满足

```
T ≥ 1 / f_c                         （与平均流：记录至少覆盖一个完整周期）
T ≥ 1 / |f_c − f_j|  对所有 j ≺ c   （与每个更高优先级分潮达到一个完整拍周期）
```

才纳入，T 为记录有效跨度（小时）。这里 `j ≺ c` 指 j 在固定优先级表中排在 c
**前面**：

```
M₂ > S₂ > N₂ > K₂ > K₁ > O₁
```

关键点（也是本版相对旧实现的修正）：比较对象是**所有优先级更高的分潮，无论它
们自己有没有被纳入**。旧实现只与"已纳取集合"比，于是被拒分潮不再挡住后面的
近邻，其能量会被后面的分潮冒名发表：

* 纯 M₂、跨度 12h：M₂ 自身周期 12.42h 未满被平均流拒；S₂ 恰好走完一个 12h
  周期，旧实现里它只需对在场的平均流负责，于是以约 27.8 cm/s 长半轴的"S₂"
  身份出现——其实整笔都是 M₂ 的能量。记录补到 60h 后同一股流又改叫 M₂。
* M₂+S₂、14 天（336h）：M₂–S₂ 拍周期 354.37h 未满，S₂ 被 M₂ 拒；K₂ 只与已
  纳入的 M₂ 比（M₂–K₂ 仅需 327.86h），于是 K₂ 进入，u 向振幅约 9.9 cm/s，
  几乎原样抄走 S₂ 的 10，而信号里根本没有 K₂。

新规则下被拒分潮**仍占着自己的频率位置**：低优先级者若与它分不开，也一并被拒，
分不开的一对不会以任何一个名字作为独立条目出现。

### 3.2 为什么是"非对称"占位，以及代价

占位是**单向**的：候选只受优先级更高者约束，低优先级者（无论纳取与否）从不反
向阻挡高优先级者。即"分不开的一对，能量记在强者名下"。另一种选择是对称的全局
两两分离（一对分不开就两个都等到拍周期），我们没有采用，代价对比：

* **采用非对称占位（现状）**：纳取时刻是一张与数据无关、与到达顺序无关的固定
  阈值表（见 3.3），实现简单、可复算；一个月以上记录的纳取集合与调和分析惯例
  一致（S₂ 在 14.8 天进入，不必等 S₂–K₂ 的半年拍周期）。代价是：被拒弱潮的
  能量仍会少量泄漏进与之近共线的强潮拟合系数（14 天处 M₂ 系数含有 S₂ 的轻
  微偏置），但不会被安上一个错误的名字单独发表；这是经典 Rayleigh 取舍的固有
  特性，记录延长后偏置自然消失。
* **若采用对称全局分离**：连 S₂ 也要等到 S₂–K₂ 的 182.6 天才纳入，一个月级
  别的常规分析反而做不了 S₂，与潮汐分析惯例及本服务"长记录结果不变"的要求
  冲突。

优先级本身按"同潮族内强者优先、半日潮早于全日潮"固定（M₂ > S₂ > N₂ > K₂；
K₁ > O₁），不随数据变化，因此结果对乱序到达不敏感。若将来要改变保守程度，
调 `RAYLEIGH_FACTOR`（如 0.8 更激进）即可。

### 3.3 临界时长（纳取阈值表）

每个分潮的纳取阈值 = max（自身一个周期，与所有更高优先级分潮的拍周期），
R = 1。该表由频率表直接算出，也是代码的实际行为：

| 分潮 | 绑定门槛 | 临界跨度 |
|------|----------|----------|
| M₂ | 自身周期 | **12.42 h** |
| S₂ | 对 M₂ 整拍 | **354.37 h（14.77 天）** |
| N₂ | 对 M₂ 整拍 | **661.31 h（27.55 天）** |
| K₂ | 对 S₂ 整拍 | **4382.91 h（182.62 天）** |
| K₁ | 对 N₂ 整拍 | **26.87 h（1.12 天）** |
| O₁ | 对 K₁ 整拍 | **327.86 h（13.66 天）** |

注意频率必须用周/小时、取**整拍** 1/|Δf|，不能用弧度频率下的 1/|Δω|（那是
半拍）：半拍处 cos/sin 交叉项仍有约 0.85 的归一化泄漏，短记录硬拟正是老脚本
"S₂、K₂ 好看却不可信"的来源。常用分潮对的整拍周期备查：M₂–S₂ 354.37h、
M₂–N₂ 661.31h、S₂–K₂ 4382.91h、N₂–S₂ 230.73h、K₁–O₁ 327.86h。

（旧文档曾把 S₂–K₂ 误写为 697.56h；按本服务频率表实算为 4382.91h。）

### 3.4 单调性

全部门槛都只是 T 的固定函数，而同一测站的记录只会变长：一个分潮在某一版进入
结果后，后续版本永远不会再被挤出去。被排除条目随跨度增加而逐个消失，顺序即
上表。

### 3.5 被谁遮住、还差多长

被排除分潮给出 `masked_by`、`required_hours`、`missing_hours`：

* 若当前跨度连该分潮的**一个完整周期**都不到，`masked_by = "mean"`，
  `required_hours` = 自身周期（常数列与潮汐列尚不可分）；
* 否则在所有未满足的高优先级拍周期门槛中，取**所需跨度最小（最近）**的那个
  分潮作为 `masked_by`，`required_hours` 为该整拍时长，
  `missing_hours = required_hours − 当前跨度`。

报"最近的一道坎"是为了让 `missing_hours` 对应眼下最先要跨过的门槛；记录增长
后遮罩对象可能切换到下一道更严的坎（例：100h 时 K₂ 报 N₂、219h 后改报 S₂），
这与判据完全一致，不是翻案。例如 14 天时 S₂ 报 `masked_by=M₂,
missing≈18.4h`，K₂ 报 `masked_by=S₂, required=4382.9h`。

"记录有效跨度"取所有**有有效流速**样本的最大时刻减最小时刻；缺测段不缩短
跨度（其影响已由最小二乘权重体现）。

## 4. 潮流椭圆换算

令复流速 `z = u + i v`，两个旋转分量为

```
W⁺ = (a_u + b_v)/2 + i(a_v − b_u)/2     逆时针（cyclonic）
W⁻ = (a_u − b_v)/2 + i(a_v + b_u)/2     顺时针（anticyclonic）
```

椭圆要素：

```
semi_major   = |W⁺| + |W⁻|
semi_minor   = |W⁺| − |W⁻|               带符号：逆时针为正，顺时针为负
inclination  = (arg W⁺ + arg W⁻) / 2  mod π    长轴自东向北的方向角
phase        = (arg W⁻ − arg W⁺) / 2  mod 2π   长轴位相
```

可直接验证的特例：

* 纯往复流（如 `u=A cos ωt, v=0`）：major=A，minor=0，inclination=0，phase=0；
  方向 θ 的直线流 `u=A cosθ cosωt, v=A sinθ cosωt` 给出 inclination=θ；
* 逆时针圆流 `u=A cosωt, v=A sinωt`：major=minor=A 且 minor > 0；
* 顺时针圆流 `u=A cosωt, v=−A sinωt`：major=A，minor=−A < 0；
* 坐标轴整体旋转 α 时，各旋转分量辐角同加 α：major/minor 不变，
  inclination 恰增 α（mod π）。

角度在接口中一律以**弧度**返回（方向角带 `_deg` 字段方便人工查看）。

## 5. 更新策略：全量重拟合（非增量）

每到一批，服务把该站**全部历史样本**读出后从头做一次拟合，并存一版不可变结果。
理由与代价：

* **理由**：拟合是“已存样本集合”的纯函数，因此
  * 乱序到达天然等价——只与样本集合有关，与到达顺序无关；
  * 批次重复上传直接短路，不产生新版本；
  * 分潮纳取集合随记录增长而变化（例如 S₂ 在跨过 354h 后进入、N₂ 在 661h
    后进入，见第 3 节阈值表），且只增不减；全量重拟合无需处理模型维度变化
    的增量合并；
  * 代码简单、可复算，任意历史版本都可完整回查。
* **代价**：计算量随站内存量 N 线性增长（正规方程组装 O(N·分潮数)，解一个
  十几阶方程组可忽略）。坐底式海流计按小时采样、运维船数天收一次，单站数万点、
  每批一次的规模下没有压力；若将来采样率大幅提高，可改为只持久化累积量
  （ΣAᵀA 分块与 ΣAᵀy，缺测行不入和），数学上与全量重拟合完全等价，但必须额外
  维护“当前分潮集合”的版本管理，本项目不采用。

数值一致性：分批重拟合与一次性拿全部数据拟合走的是**同一段确定性代码、同一
组排序后的样本**，浮点运算顺序相同，结果逐比特一致（远严于振幅相对差 1e-9、
相位差 1e-7 弧度的验收要求；测试以该容差断言）。

## 6. 存档与幂等

* 每收一个**内容不同的新批次**，产生 `version = 1,2,3,…`（按站内已存批次计数），
  结果整体序列化存入 SQLite，任何版本可按编号回查；
* 批次幂等键为 `(station_id, batch_id)`；内容指纹为
  `sha256(规范化JSON(batch_id, 按时间排序的样本)))`。相同内容重复上传返回最新版
  并标记 `replayed=true`，不写新版本；同号不同内容返回 409；
* 样本时间在站内唯一（`(station_id, t_hours)` 主键），跨批次重叠时刻报 422 并
  指出具体样本下标；
* 所有状态在 SQLite 单一文件中（WAL 模式），文件位于挂载卷 `/data`，重启后
  测站、批次、每一版结果均保留。
